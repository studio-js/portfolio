해커톤 실습용 합성 데이터

40일 해커톤에서 수강생이 분석할 데이터 3종을 멀티 에이전트 워크플로로 만들고 검증했습니다. 실제 운영 기록에는 개인정보가 있어서 공개 통계와 집계표만으로 합성했습니다.

역할
에이전트별 모델 배정과 검증 기준, 데이터 3종의 구성 결정. 비식별 방식은 사내 IT와 협의
AI 활용
Claude Code 에이전트로 생성기와 검증 코드 구현, 블라인드 분석과 채점
기술
Claude Code(서브에이전트, 워크플로 스크립트), Python(pandas, NumPy, SciPy), Parquet
규모
표 96개, 3,068만 행

에이전트 구성

원천 데이터 준비, 생성기 구현, 독립 검증을 서로 다른 서브에이전트에 배정했습니다. 설계와 검증은 Claude Fable로, 구현은 Claude Opus로 진행했습니다.

역할하는 일허용한 도구
원천 데이터 준비공개 통계를 내려받아 정해진 스키마로 저장파일 읽기와 쓰기, 셸, 웹 검색
생성기 구현생성 명세대로 단계별 코드를 작성파일 읽기와 쓰기, 셸
독립 검증생성된 표에서 검증 항목의 값을 다시 계산파일 읽기, 셸⁠(파일 편집 도구 없음)
  • 에이전트마다 실제 집계와 정답표를 접근 금지 경로로 지정
  • 공개할 문서에 숨겨야 하는 값이 있는지 자동으로 검사
  • 모든 서브에이전트 프롬프트에 개인정보를 외부 요청에 넣지 않는다는 지침을 포함

워크플로 스크립트가 단계마다 에이전트를 실행하고 에이전트는 상태와 지적 사항을 정해진 형식으로 반환합니다. 검증에서 지적이 나오면 앞 단계로 돌아가 고쳤습니다. 금융 데이터는 5차례, 의료⁠·⁠보건 데이터는 6차례 보완했습니다.

블라인드 분석

정답표와 생성 코드를 받지 않은 에이전트가 수강생에게 줄 자료만으로 분석 질문에 답하고 다른 에이전트가 그 답을 정답표와 대조해 채점합니다. 분석 에이전트가 접근 금지 경로를 열지 않았는지는 도구 호출 기록으로 확인했습니다.

  1. 1에이전트분석수강생에게 줄 자료만 보고 분석 질문에 답함
  2. 2코드경로 점검도구 호출 기록에서 접근 금지 경로를 열었는지 확인
  3. 3에이전트채점다른 에이전트가 정답표와 대조

심층 모의 분석의 주장 87개 가운데 정답이 72개, 부분 정답이 9개, 오답이 1개였습니다. 이 과정에서 자동 검사가 놓친 데이터 누수도 찾았습니다. 가격 열만 보면 결제 완료 여부가 드러났습니다.

검증

생성에 쓴 통계로 검증하면 구현 오류밖에 찾지 못하므로 검증에는 생성에 사용하지 않은 외부 통계를 썼습니다. 분석 과제의 정답이 될 효과는 미리 정한 크기로 넣었고 생성된 데이터에서 그 효과가 다시 검출되는지도 확인했습니다. 결과를 본 뒤 데이터를 다시 맞추면 검증이 되지 않으므로 외부 통계와 맞지 않은 항목⁠(금융 47개)⁠은 데이터를 그대로 두고 원인과 함께 데이터 정의서에 적었습니다.

생성 방식과 가정

금융과 의료⁠·⁠보건 데이터는 공개 통계를 확률 규칙으로 바꿔 가상 개인을 한 명씩 생성했고 이커머스는 5건 미만을 숨긴 집계에서 분포만 가져왔습니다. 실제 개인의 기록은 받지 않았습니다.

날짜에는 2022~2026년의 실제 사건 200개를 반영했습니다. 날짜는 정부 원문과 보도에서, 크기는 통계연보와 한국은행 자료에서 가져왔고 확인이 약한 사건은 가정으로 표시했습니다.
