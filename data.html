해커톤 실습용 합성 데이터

40일 해커톤에서 수강생이 분석할 데이터 3종을 멀티 에이전트로 만들었습니다. 그 가운데 금융⁠(카드 소비)⁠과 의료⁠·⁠보건 데이터는 공개 통계로 가상 개인 3만 명의 기록을 생성했습니다. 역할마다 읽기 범위와 쓰기 범위를 정하고 정답표를 받지 않은 에이전트에게 과제를 풀게 해서 배포하기 전에 데이터를 평가했습니다.

역할
데이터 3종의 구성과 수강생 제공 범위, 모델 배정과 검증 기준 결정
AI 활용
Claude Code 에이전트로 생성기와 검증 코드 구현, 블라인드 분석과 채점. 설계와 검증은 Claude Fable, 구현은 Claude Opus
기술
Claude Code(서브에이전트, 워크플로 스크립트), Python(pandas, NumPy, SciPy), Parquet
규모
금융 1,493만 행, 의료⁠·⁠보건 951만 행, 표 40개

권한과 감사

생성 에이전트와 검증 에이전트를 나누고 역할마다 읽기 범위와 쓰기 범위를 정했습니다. 블라인드 분석 에이전트가 허용하지 않은 경로에 접근했는지는 작업이 끝난 뒤 도구 호출 기록에서 확인했습니다.

대화와 실행 기록에 나온 내용은 해외 서버의 언어 모델에 전달됩니다. 그래서 원천마다 출력해도 되는 범위를 생성기 작업 지침에 정했고 서브에이전트 프롬프트의 첫머리에서 개인정보를 외부 요청에 넣지 말라고 지시했습니다.

블라인드 분석과 채점

수강생 배포본만 받은 분석 에이전트가 분석 질문에 답하고 데이터마다 채점 에이전트가 분석 결과를 정답표와 대조했습니다. 배포 직전의 심층 모의 분석에서 금융과 의료⁠·⁠보건을 맡은 분석 에이전트 4개는 모두 허용하지 않은 경로에 접근한 호출이 없었습니다.

블라인드 분석은 데이터를 보완하면서 여러 번 반복했습니다. 의료⁠·⁠보건 데이터의 3차 블라인드 분석을 채점하다가 검증 단계의 자동 검사 하나가 계절 추세를 통제하지 않아 정답표의 측정값이 생성할 때 설정한 값과 다르다는 것을 찾았습니다. 그 검사를 고친 뒤 측정값이 설정한 값과 일치했고 데이터는 바꾸지 않았습니다. 배포 직전의 심층 모의 분석에서는 두 데이터 모두 고칠 결함이 나오지 않았습니다.

데이터 모델

데이터마다 표의 키, 관계, 코드표를 스키마 정의로 관리하고 데이터 정의서는 이 정의에서 스크립트로 생성했습니다. 생성기 구현 에이전트가 스키마를 바꿔야 하면 작업 지침부터 고치고 변경 내역을 기록하게 했습니다. 정의서와 CSV는 전수 대조해 불일치를 0건으로 맞췄습니다.

생성 방식과 검증

금융과 의료⁠·⁠보건 데이터는 공개 통계를 확률 분포로 바꿔 가상 개인을 한 명씩 생성했습니다. 값은 에이전트가 작성한 생성기 코드가 계산했습니다.

날짜에는 2022~2026년의 실제 사건 200개를 반영했고 근거가 약한 사건은 가정으로 표시했습니다.

생성에 사용하지 않은 외부 통계로만 검증했습니다. 일치하지 않은 항목은 원인과 함께 데이터 정의서에 기록했습니다. 분석 과제의 답이 될 효과는 생성할 때 미리 넣고 생성한 데이터에서 다시 검출되는지 확인했습니다.
