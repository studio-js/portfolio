합성 데이터 생성

40일 해커톤에서 수강생이 분석할 데이터 3종을 멀티 에이전트 워크플로로 생성하고 검증했습니다. 실제 운영 기록은 개인정보 때문에 제공할 수 없어서 공개 통계와 집계표만으로 새 기록을 생성했습니다.

역할
에이전트별 모델 배정, 검증 기준, 데이터 3종의 구성과 제공 범위, 비식별 방식 결정과 사내 IT 협의
AI 활용
Claude Code 에이전트로 생성기와 검증 코드 구현, 블라인드 분석과 채점, 근거 보고서와 발표 자료 작성
기술
Claude Code(서브에이전트, 워크플로 스크립트), Python(pandas, NumPy, PyArrow, SciPy, scikit-learn), YAML 설정, Parquet
규모

에이전트 구성

원천 준비, 생성기 구현, 독립 검증을 서로 다른 서브에이전트에 배정했습니다. 자료 취급, 코드 규칙, 표 계약, 검증 기준은 문서로 정의했고 에이전트는 작업 전에 이 문서와 역할 정의 파일을 읽습니다.

역할하는 일허용한 도구
원천 준비공개 통계를 내려받아 정리하고 표 계약대로 저장파일 읽기와 쓰기, 셸, 웹 검색
생성기 구현표 계약과 생성 명세대로 단계별 코드를 작성하고 자체 검사 뒤 보고파일 읽기와 쓰기, 셸
독립 검증검증 기준과 공개 위험을 산출물에서 다시 계산해 지적 목록을 작성파일 읽기, 셸⁠(파일 쓰기 도구 없음)

설계, 검증, 감사는 Claude Fable로, 구현은 Claude Opus로 실행했습니다.

  • 에이전트마다 실제 집계와 정답표를 접근 금지 경로로 지정
  • 실제 집계는 화면에 비율만 출력
  • 공개 문서에 금칙어와 숨겨야 하는 값이 있는지 자동으로 검사
  • 모든 서브에이전트 프롬프트 첫 문단에 개인정보를 외부 요청에 넣지 않는다는 지침을 포함

워크플로

워크플로 스크립트가 원천 준비, 생성기 구현, 실행과 검증, 수정의 단계마다 에이전트를 실행합니다. 에이전트는 상태, 산출물, 지적 사항을 정해진 형식으로 보고하고 지적 사항에는 심각도를 3단계로 붙입니다. 메인 세션은 보고를 통합한 뒤 다시 검증합니다.

검증에서 지적이 나오면 앞 단계로 돌아가서 고쳤습니다. 금융 데이터는 5차례, 의료·보건 데이터는 6차례 보완했고 보완도 워크플로 스크립트로 실행했습니다.

메인 세션은 작업 기록과 할 일 목록을 남겨서 컨텍스트가 압축된 뒤에도 작업을 이어 갔습니다.

블라인드 분석

정답표와 생성 코드를 볼 수 없는 에이전트가 수강생에게 줄 자료만으로 분석 질문에 답하고 다른 에이전트가 그 답을 정답표와 대조해 채점합니다. 분석 에이전트에게는 공개 자료 폴더만 읽도록 지시했고 지시를 지켰는지는 도구 호출 기록으로 확인했습니다.

  1. 1에이전트분석수강생에게 줄 자료만 보고 분석 질문에 답함
  2. 2코드감사도구 호출 기록에서 금지 폴더를 열었는지 확인
  3. 3에이전트채점다른 에이전트가 정답표와 대조

채점한 주장 174개 중 정답이 139개, 부분 정답이 32개, 오답이 0개였습니다. 나머지 3개는 답하지 않았거나 채점하지 못한 주장입니다.

블라인드 분석에서 찾은 결함

할인율이 정확히 0.9인 주문의 97.9%⁠가 결제 완료여서 가격 열만으로 결제 완료 여부를 맞힐 수 있었습니다⁠(AUC 0.977). 결제 상태에 따라 할인율의 반올림이 달랐던 것이 원인이었고 반올림을 통일해서 이 비율을 27.2%⁠로 낮췄습니다.

이전 결제 체계 주문의 29%⁠는 주문 시각이 계정을 만든 시각보다 앞섰습니다. 시각을 기록에 맞춰 다시 배치하고 순서 검사 4개를 추가해서 없앴습니다.

의료·보건 데이터에서는 채점 과정에서 기온과 미세먼지 계수를 계산하는 자동 검사의 약점이 드러나서 검사를 고쳤습니다.

검증

검증에는 생성에 쓰지 않은 외부 자료를 썼습니다. 생성에 쓴 통계와 다시 비교하면 구현 오류만 찾을 수 있고 값이 현실과 맞는지는 알 수 없기 때문입니다.

데이터

사내 IT는 실제 기록과 1:1로 대응하는 행이 없어야 한다는 조건을 걸었습니다. 이름과 번호만 지우는 가명 처리는 원래 행이 남아서 이 조건에 맞지 않습니다. 그래서 집계표와 공개 통계를 확률로 바꾼 뒤 그 확률에 따라 행을 한 건씩 새로 생성했습니다.

값은 에이전트가 작성한 생성기 코드가 계산했고 언어 모델이 값을 직접 만들지는 않았습니다. 생성한 이커머스 운영 표에 원본 운영 표와 같은 행은 없습니다.

표의 키, 관계, 코드표는 표 계약으로 정의했고 데이터 정의서는 스크립트로 생성합니다. 표 사이의 관계는 이커머스 81개, 금융 25개, 의료·보건 28개입니다.

캠페인이나 알림처럼 분석 과제의 정답이 될 효과는 미리 정한 크기로 설정했습니다. 정답표에는 설정한 값이 있고 수강생에게는 공개하지 않습니다.
