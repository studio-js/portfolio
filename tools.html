전후 비교

문체 검수 스킬

에이전트가 쓴 교안을 검수하면서 직접 지적한 표현 120건을 종류별로 나눠 체크리스트로 만들었습니다. 수정 에이전트가 이 체크리스트에 따라 고치고 검수 에이전트가 원문과 대조합니다.

같은 교안 3편을 이전 방식⁠(외부 윤문 스킬)⁠과 새 방식으로 각각 고쳐 비교한 뒤 새 방식을 채택했습니다.

이전 방식새 방식
고친 글에 남은 검사 위반같은 교안 3편을 방식별로 따로 고친 결과
이전 방식 9건새 방식 1건
검수 에이전트가 고쳐야 한다고 표시한 곳
이전 방식 72곳새 방식 39곳
글 1편에 쓴 토큰에이전트 호출은 4번에서 3번으로 감소
이전 방식 약 82만새 방식 약 71만

다이어그램 스킬

matplotlib의 기본 설정으로는 한글이 네모로 깨집니다. 이 스킬은 한글 글꼴을 고르고 강조할 값 하나만 진한 색으로 칠하며 값은 막대 끝에 직접 적습니다. 그림을 저장할 때는 글자와 선이 겹치는지 검사해서 겹치면 저장하지 않습니다.

교안 검수 에이전트

수강생 역할의 에이전트가 교안을 처음부터 읽고 막힌 곳을 표시합니다. 표시된 곳을 고치고 다시 읽게 하는 과정을 반복했습니다.

교차 검증 스킬

Claude가 쓴 초안을 GPT와 DeepSeek 계열의 검토 에이전트가 각각 검토하고 그 검토 의견을 반영해 다시 구현합니다. 시연 과제로 함수 하나를 정해 같은 테스트 14건으로 채점했습니다.

단독 초안교차 검증
통과한 테스트⁠(14건 가운데)단독 초안은 잘못된 입력 5개를 오류로 처리하지 못함
단독 초안 9건교차 검증 14건

개발 환경 가드레일 훅

에이전트가 실행하려는 셸 명령과 MCP 도구 호출을 훅이 먼저 검사합니다. 차단 항목에 해당하면 실행을 막고 차단 사유를 에이전트에게 반환합니다.

이름하는 일쓰는 곳
개발 환경 가드레일 훅.env 읽기, PR 병합, 로컬 Docker 실행을 차단. 테스트 케이스 158건으로 검증LMS 개발 환경

파일 편집 도구를 뺀 검수 에이전트교안을 검수하는 에이전트에는 파일 편집 도구를 주지 않음교안 제작

검증과 평가

이름하는 일쓰는 곳
수용 테스트 우선 작성평가 에이전트가 구현보다 먼저 테스트를 쓰고 하네스가 그 테스트를 직접 실행LMS 개발 에이전트 키트
교안 린터노트북의 규격, 문체, 분량, 그림을 검사. 검사 함수 227개교안 제작

독립 검증과 블라인드 분석파일 편집 도구를 뺀 에이전트가 검증 항목의 값을 다시 계산. 정답표를 받지 않은 에이전트가 분석합성 데이터 생성

업무 프로세스 표준화

워크플로 4개⁠(교안 제작, LMS 프로토타입 제작, 뉴스 발행, 합성 데이터 생성)⁠마다 단계, 담당 에이전트, 자동 검사, 사람이 확인할 항목을 정의 파일 하나에 적었습니다. 단계를 마친 에이전트가 단계 보고서를 만들고 사람이 결정을 기록해야 다음 단계를 시작하도록 스킬로 만들었습니다.

승인 기록은 사람이 터미널에서 실행한 명령으로 남기게 했고 에이전트가 도구 호출로 이 기록을 쓰거나 승인 명령을 실행하면 가드레일 훅이 막게 했습니다. 승인 기록에는 보고서의 해시를 남겨 승인한 뒤 보고서가 바뀌면 다음 단계가 다시 막힙니다. 훅의 차단과 해시 대조는 자체 시험 72개 항목으로 확인했습니다.
